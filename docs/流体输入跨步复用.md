# 第二阶段：MUSCL 直接使用上一反应的设备状态

开关：`EU3D_RESIDENT_MUSCL=1`，默认关闭。依赖 `EU3D_RESIDENT_EE=1` 和已有上传复用路径。

## 数据流

第一步没有上一反应状态，仍完整上传。后续步骤：

1. 上一反应完成后，发布设备端内部网格状态的只读视图。
2. 从状态中取 P、D、U、V、W、H、Gamma、Yi，写入 GPU MUSCL 输入缓冲区。
3. x 两侧执行与 CPU 相同的镜像复制。
4. y 前侧仍使用 CPU 重新计算的热力学结果，只上传这片边界；y 后侧在 GPU 镜像复制。
5. z 两侧最后复制，并反转 W，保证棱边、角点与 CPU 边界更新顺序一致。
6. 三个方向共享这些输入，原 MUSCL 和 AUSM kernel 不变。
7. EE 开始修改状态前使视图失效；只有下一反应结束才重新发布。

CPU 完整边界、反应结果下载和主机拆包仍保留。因此这是向 GPU 常驻推进的中间阶段，不是完整 GPU 常驻。

前侧边界的热力学重新计算暂不迁移，避免把浮点分支差异混入这次数据复用优化。

## 支持范围

仅当前单 rank、固定时间步、EE/MUSCL_2、自适应反应、关闭 DLB 的 RSBI 路径。每个方向内部尺寸至少为 bc。网格尺寸和物种数必须与设备状态匹配，不匹配时报错。

今后若改变边界类型或在 CPU 修改内部流场，需要同步修改或禁用该路径；不能直接把这个专门对应 RSBI 边界的实现推广到其他边界。

跨阶段只共享只读设备指针，仍由 EE 存储对象拥有，不额外复制 ReactionFlowState。主机侧共享视图定义于 `include/ResidentMusclState.hpp`；假定单主机线程按当前顺序调用。

## 使用

```bash
make -j2
EU3D_RESIDENT_EE=1 EU3D_RESIDENT_MUSCL=1 bash scripts/run_local.sh 100
```

关闭 MUSCL 开关即可回到上一阶段；两个 RESIDENT 开关都关闭则回到整理时的上传路径。

```bash
bash tests/validate_resident_muscl.sh
bash scripts/benchmark_resident_muscl.sh
```

## 验证

2026-10-18，本机 RTX 3050 Laptop，CUDA 12.5，sm_86，281×141×2：

- 3 步与 100 步最终导出状态：所有字段最大绝对差为零。
- 100 步中 99 次流体输入复用：P/D/U/V/W/H/Gamma/Yi 的全部内部网格、halo、棱边和角点与 CPU 输入逐位一致。
- 100 次 EE 独立参考检查通过。
- 原上传复用测试：9 个 sweep，所有方向、同地址输入改变、尺寸改变及独立调用，通量位级一致。

验证目录：`runs/resident_muscl_check_NexmQcVY/`。这些验证仅说明本次改动与自己的旧路径一致，不消除与 CPU 或第三方版本已有的数值差异。

## 上传量

NS=9、bc=2、281×141×2 时，流体输入第一步仍上传 31,737,600 字节。从第二步开始，仅上传 y 前侧 145,920 字节，约减少 99.54%。这不是程序总传输量减少 99.54%，也不代表总耗时减少相同比例。

原文件保存在 `archive/resident_muscl_baseline/`。

## 本轮性能结果

同一本机、同一可执行文件、281×141×2、100 步，交替运行三轮，关闭验证与状态导出。两组均开启上一阶段 RESIDENT_EE，仅切换 RESIDENT_MUSCL。

| 三轮中位数 | 关闭本轮优化 | 开启本轮优化 |
| --- | ---: | ---: |
| 主循环 | 17.9243 s | 17.3738 s |
| 总时间 | 21.3223 s | 20.2200 s |

主循环耗时再降低 3.07%。这是笔记本单卡的小网格结果，尚未测量 A800 或多卡性能。CPU 边界处理、反应结果下载及回填仍存在，尚未实现全流程 GPU 常驻。

性能原始目录：`runs/resident_muscl_perf_sMSs6R4Q/`；汇总及正确性对比记录保存在 `docs/resident_muscl_results/`。
