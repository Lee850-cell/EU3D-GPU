# 第一阶段：反应结果跨步复用于 EE

新增开关 `EU3D_RESIDENT_EE=1`，默认关闭。

## 改动

原路径每个时间步将 CPU 上完整 CS、T、E 复制到锁页内存，再上传 GPU，随后执行 CS += RHS 和状态恢复。

新路径第一步仍从主机初始化。反应结束后保留已更新的设备端 ReactionFlowState；下一步直接在该状态的 conserved 上累加新的 RHS，再执行同一个状态恢复 kernel。温度和内能沿用上一步反应的结果。状态恢复、反应积分的数学表达式未修改。

281×141×2、bc=2、NS=9 时，第 2 步起每步省去 29,754,000 字节的输入主机复制及 H2D 传输。热力学常数的小量上传仍保留。

## 生命周期与限制

- 每次进入 Euler::Computing 重置有效性，第一步强制从主机初始化。
- 只有反应完成且设备指针、物种数、网格数一致，才允许下一步复用。
- 尺寸变化或没有有效的上一反应状态时，从主机重新初始化。
- 仅支持单 rank、固定 dt、GPU EE/MUSCL_2、自适应 Trapezoid、DLB 关闭、CHAIN_STATE 与 EE_STATE 开启的路径；不支持的配置明确报错。
- 当前 CPU 物理边界只修改 ghost cells，复用的状态只包含内部单元。如果以后增加 CPU 内部源项、滤波或修改内部 CS/T/E，必须增加显式失效处理或禁止本开关。
- EU3D_VALIDATE_EE_STATE=1 可与新路径共同使用，以 CPU 上传路径为独立参考，逐步比较所有状态字段。
- 这不是完整 GPU 常驻：反应下载、主机拆包、CPU 边界、流体输入上传仍存在。下一阶段才处理这些依赖。

## 使用

```bash
make -j2
EU3D_RESIDENT_EE=1 bash scripts/run_local.sh 3
EU3D_RESIDENT_EE=1 bash scripts/run_local.sh 100
```

验证与性能测试（均为本机单 GPU 小网格）：

```bash
bash tests/validate_resident_ee.sh
bash scripts/benchmark_resident_ee.sh
```

脚本会生成独立 runs 子目录。性能脚本关闭验证与状态导出，off/on 交替各三次。

## 初次验证记录

本机 CUDA 12.5、sm_86、RTX 3050 Laptop，281×141×2。

- 编译通过。
- 三步和 100 步：全部导出字段最大绝对差为零。
- 优化路径三步及 100 步的 EE 独立参考检查全部通过，comparison=exact。
- 日志：`runs/resident_ee_check/`。

这些结果证明本次变更相对旧 GPU 路径的回归通过，不改变此前 CPU 与 GPU、我们与第三方版本之间尚未解决的数值差异。

原始三份修改文件保存在 `archive/resident_ee_baseline/`；关闭开关也可直接使用原上传路径。

## 本机性能结果

100 步，off/on 交替各三次，关闭全部验证和状态导出。

|指标中位数|原路径|跨步复用|
|---|---:|---:|
|主循环|18.9310 s|17.9422 s|
|程序总时间|21.9367 s|20.7331 s|

主循环耗时下降 5.22%。这仅是本机小网格结果，尚未测 A800 或多卡；新开关目前主动限制为单卡单 rank。

原始计时日志：`runs/resident_ee_perf_fs5f5Ln1/`。汇总与验证摘要保存在 `docs/resident_ee_results/`。
