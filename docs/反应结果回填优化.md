# 反应结果回填优化

## 修改范围

`include/PackedReactionCopy.hpp` 增加固定长度行复制；`src/Euler.cpp` 通过 `EU3D_FAST_UNPACK=1` 选择。默认关闭。GPU 化学反应算法、下载内容、浮点运算和 halo 均不改变。

原实现对每个 i、j 行调用动态长度 memcpy。新实现在每行元素数为 2、18、26 时使用编译期固定长度 memcpy，使编译器可以内联；每行地址通过指针递增。其他行长保留原路径。这些行长对应 nk=2、NS=9 的标量、组分和守恒量，也可服务具有相同行长的其他网格。

本轮是薄网格 CPU 回填开销实验，不是全流程 GPU 常驻，不减少 PCIe 下载量。nk=16 通常不会进入这些特化路径。

## 验证与复现

```bash
# 在 EU3D 目录执行
g++ -std=c++17 -O3 -Iinclude tests/test_packed_copy.cpp -o /tmp/eu3d_test_packed_copy
/tmp/eu3d_test_packed_copy
bash tests/validate_fast_unpack.sh
bash scripts/benchmark_fast_unpack.sh
```

独立测试覆盖 double/int、不同网格尺寸、halo 厚度及组分宽度，通过独立索引计算检查所有内部数据和未写入的 halo。整程序测试以同一可执行文件开关对照，并开启原有 Packed output validation，比对全数组及 halo；最终导出字段要求最大绝对差为零。

性能比较两组均开启 RESIDENT_EE、RESIDENT_MUSCL，只切换 FAST_UNPACK；关闭验证、跟踪与状态导出，交替三次 100 步。

## 2026-10-18 结果与决定

RTX 3050 Laptop、CUDA 12.5、281×141×2、100 步：

- 独立复制测试通过。
- 3 步、100 步整程序最终状态最大绝对差均为 0。
- 开启优化的 100 次 packed output 全数组检查通过，包含 halo。

| 三轮中位数 | 关闭 FAST_UNPACK | 开启 FAST_UNPACK |
| --- | ---: | ---: |
| 主循环 | 17.1133 s | 17.1487 s |
| 总时间 | 20.2354 s | 19.9814 s |

主循环中位数增加约 0.21%，三轮波动大于差值，不能证明有稳定收益。保持默认关闭，仅作为可复现实验保留；不将它计入已实现的加速比。总时间变化也不足以证明此回填改动有稳定收益。

验证目录 `runs/fast_unpack_check_eES61Jes/`，性能目录 `runs/fast_unpack_perf_y8VIhC9A/`，摘要保存在 `docs/fast_unpack_results/`。

后续重点应转向减少每步完整下载/回填。需要同时处理 CPU 边界读取、D/T 的 NaN 检查，以及 Output 和状态导出前的主机同步；不能只跳过回填而让这些路径读取旧状态。
